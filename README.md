## ⭐ How it works

- GitHub Actions runs as an uptime monitor
  - Every 5 minutes, a workflow visits each endpoint to make sure it's up
  - Response time is recorded and committed to git
  - Graphs of response time are generated daily
- GitHub Issues is used for incident reports
  - An issue is opened automatically when an endpoint goes down, and closed when it recovers
  - Slack and Microsoft Teams notifications are sent on updates (see below)
- GitHub Pages hosts the status website at https://codbex.github.io/upptime-monitoring

## 🔔 Notifications (Slack & Microsoft Teams)

Notifications are configured via **GitHub repository secrets** (Settings → Secrets and variables → Actions), not in `.upptimerc.yml`. The Uptime workflow reads them through `SECRETS_CONTEXT`.

### Slack

Create an [incoming webhook](https://slack.com/intl/en-in/help/articles/115005265063-Incoming-webhooks-for-Slack) for the target channel, then add these secrets:

| Secret name | Value |
| --- | --- |
| `NOTIFICATION_SLACK` | `true` |
| `NOTIFICATION_SLACK_WEBHOOK` | `true` |
| `NOTIFICATION_SLACK_WEBHOOK_URL` | your Slack webhook URL |

### Microsoft Teams

Create an [incoming webhook](https://learn.microsoft.com/en-us/microsoftteams/platform/webhooks-and-connectors/how-to/add-incoming-webhook) for the target channel, then add these secrets:

| Secret name | Value |
| --- | --- |
| `NOTIFICATION_TEAMS` | `true` |
| `NOTIFICATION_TEAMS_WEBHOOK_URL` | your Teams webhook URL |
